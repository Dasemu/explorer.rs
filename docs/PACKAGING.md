# Packaging

How the Windows release artifacts are built. Everything runs on Linux with
`cargo xwin`; nothing needs a Windows machine.

```
scripts/build-windows.sh
  -> dist/explorer-rs-setup-<version>-x64.exe                (installer, ~6 MB)
  -> dist/explorer-rs-<version>-x86_64-pc-windows-msvc.zip   (portable)
```

## Pipeline

1. **Release binaries** for `x86_64-pc-windows-msvc`:
   supervisor (`explorer-rs.exe`), taskbar (default features, or
   `TASKBAR_FEATURES=...`), launcher (`file-index,everything`, override with
   `LAUNCHER_FEATURES`), `explorer-rs-indexd.exe`,
   `explorer-rs-index-helper.exe`, and `explorer-rs-settings.exe` (the
   unelevated "explorer.rs settings" helper from `crates/explorer-setup`).
2. **Stage** `dist/payload-<version>/`: every `explorer-rs*.exe` except
   `explorer-rs-setup.exe` (so a future `explorer-rs-desktop.exe` is picked
   up automatically), `LICENSE`, `config/default.toml` as
   `config.example.toml`, `docs/INSTALL.md`, `docs/RECOVERY.md`,
   `scripts/*.ps1`. The staged tree is exactly the install-folder layout.
3. **Pack** with the host tool `explorer-setup-pack <out> <version> <dir>`
   (a binary of `crates/explorer-setup`), which also re-reads and verifies
   the result.
4. **Embed**: `EXPLORER_RS_PAYLOAD=<payload> cargo xwin build -p explorer-setup
   --bin explorer-rs-setup`. `crates/explorer-setup/build.rs` passes the path
   to `include_bytes!`. Without the variable an empty payload is embedded, so
   `cargo check`, clippy and tests work without step 1-3; such a setup
   refuses to install ("built without a payload").
5. **Portable zip**: the staged files plus `.pdb` files and
   `TESTING-ON-WINDOWS.md`.

At install time the setup copies itself into the install folder as
`uninstall.exe` and writes `install-manifest.txt` (the installed file list,
used for upgrades and uninstall so only our own files are ever deleted).

## Payload format (version 1)

All integers little-endian. Implemented and tested in
`crates/explorer-setup/src/payload.rs`.

```
magic   "XRSPAYLD" (8 bytes)
format  u32 = 1
version u16 length + UTF-8 product version
count   u32
entries (count times):
  path    u16 length + UTF-8, relative, '/'-separated
  method  u8: 0 stored, 1 raw DEFLATE (miniz_oxide)
  size    u64 uncompressed size
  stored  u64 stored size
  sha256  32 bytes, of the uncompressed data
  data    stored bytes
trailer SHA-256 of everything above (32 bytes)
```

`unpack` verifies the trailer, every field, every path (no `..`, no absolute
or drive paths, no characters or device names Windows forbids, no duplicates
ignoring case) and every per-file hash before the installer writes anything.
Tests flip every single byte of a sample payload and check that each
corruption is detected.

## Resources (icon, manifest, version info)

Every binary crate has a `build.rs` that includes
`assets/build/resources.rs`:

```rust
// SPDX-License-Identifier: GPL-3.0-or-later
include!("../../assets/build/resources.rs");
fn main() {
    embed_resources(&[Bin::new("explorer-rs-desktop", "explorer.rs desktop")]);
}
```

(For a new binary crate, e.g. `explorer-rs-desktop`, that is the whole
`build.rs`. Use `.require_admin()` only for the installer.)

For Windows MSVC targets it writes a manifest from
`assets/manifests/app.manifest.in` and an `.rc` file into `OUT_DIR`,
compiles them with `llvm-rc` (or `$RC`, or `rc.exe` on Windows) and links the
`.res` into that binary only (`cargo:rustc-link-arg-bin`). On other targets
it does nothing, so Linux builds and tests are unaffected. Without a
resource compiler the build continues with a warning.

- **Manifest**: PerMonitorV2 DPI awareness (`dpiAware true/pm` fallback),
  Common Controls v6, `supportedOS` Windows 10/11, `longPathAware`,
  `activeCodePage UTF-8`, `requestedExecutionLevel asInvoker`
  (installer: `requireAdministrator`).
- **VERSIONINFO**: CompanyName "explorer.rs contributors", ProductName
  "explorer.rs", per-binary FileDescription, version from Cargo.
- **Icon**: `assets/explorer-rs.ico` (16-256 px), generated by
  `python3 assets/make-icon.py` (Pillow). Original artwork: a blue-teal
  rounded square with three white bars; it resembles no Microsoft mark.

Check a build with `llvm-readobj --coff-resources <exe>`.

## Signing

Not done yet. When a certificate exists: sign the staged `.exe` files after
step 2, then sign `explorer-rs-setup-*.exe` after step 4
(`signtool sign /fd SHA256 /tr <timestamp-url> /td SHA256 ...`). Signing the
setup alone leaves the installed binaries unsigned.

**TESTING-ON-WINDOWS.md (new section "Installer"):**

1. Run `explorer-rs-setup-<ver>-x64.exe`. Expect SmartScreen (More info ->
   Run anyway) and a UAC prompt; the wizard shows in your Windows language
   (English or Spanish) and in dark mode if apps use dark mode.
2. Welcome -> Next. Options: "Run alongside" selected, Fast file search and
   Start now ticked, folder `C:\Program Files\explorer-rs`. Click Install.
3. Expect the progress list to finish without errors, explorer.rs to start
   next to Windows Explorer, and NOT elevated (Task Manager -> Details ->
   add column "Elevated": explorer-rs*.exe = No, except
   explorer-rs-index-helper.exe = Yes).
4. Check: Start menu folder "explorer.rs" with 4 shortcuts; Settings -> Apps ->
   Installed apps lists explorer.rs 0.x by "explorer.rs contributors";
   `taskschd.msc` -> explorer-rs -> IndexHelper (run with highest
   privileges, at log on of you); `reg query HKCU\Software\Microsoft\Windows\CurrentVersion\Run /v explorer-rs`.
5. Click "explorer.rs settings": Notepad opens `%APPDATA%\explorer-rs\config.toml`
   without a UAC prompt.
6. Sign out and in: explorer.rs starts alongside Explorer.
7. Run the installer again (upgrade): previous choices pre-selected; while
   explorer.rs runs, it is closed and restarted; no reboot asked.
8. Shell mode (VM with snapshot!): run the installer, choose Replace; after
   Done, sign out/in: explorer.rs is the shell. Then use Start menu ->
   "Restore Windows Explorer" (needs `--restore-explorer`) or Ctrl+Alt+Shift+E.
9. Upgrade while explorer.rs is the shell: the Options page shows the red
   "explorer.rs is your shell right now" note; after Install the taskbar
   comes back (started via the `\explorer-rs\Launch` task).
10. Over-the-shoulder elevation: as a standard user, run setup and enter
    another admin's credentials. Run value / shell must be written for the
    standard user (check with `reg query HKCU\...` as that user).
11. Uninstall from Installed apps with "Also remove my settings" unticked:
    files, shortcuts, tasks and ARP entry are gone; `%APPDATA%\explorer-rs`
    is kept; Windows Explorer is the shell. With the box ticked, both
    AppData folders are gone.
12. Silent: `explorer-rs-setup.exe --silent --mode=none --file-search=off`
    then `echo %ERRORLEVEL%` (0); `"C:\Program Files\explorer-rs\uninstall.exe"
    --uninstall --silent` (0).
13. Check `C:\ProgramData\explorer-rs\setup.log` for every run.
